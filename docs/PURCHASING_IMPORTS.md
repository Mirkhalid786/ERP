# Suppliers, Medicine Catalogue & Supplier Bill Import

## 1. Supplier registration (simplified)
**Required:** Display / Trade Name only (2–200 characters).

**Optional, on the main form:** registered legal name, GSTIN, state code, phone, contact person.

**Optional, under "Additional details":** drug licence (Form 20B/21B), email, payment terms (default 30 days),
credit limit, city, state, pincode, full address, notes, active/inactive.

GST rules (unchanged in substance, now applied consistently on create and edit):
- A blank GSTIN or state code is accepted and stored as "not provided".
- A GSTIN that is entered must be a valid 15-character GSTIN. Spaces and lower case are tidied automatically
  (`27 aabca 1234f1z5` becomes `27AABCA1234F1Z5`). Anything else is rejected with a message under the GSTIN field.
- With a valid GSTIN, the state code is its first two digits. The form fills it in. A different state code is rejected
  under the State code field, because CGST/SGST versus IGST depends on it.
- Without a GSTIN, the state code is optional. If given, it must be a GST state code (01–38, 97, 99); "7" becomes "07".
- Validation errors appear next to each field, never as raw JSON.

## 2. Medicine catalogue import
**Where:** Medicines → *Import catalogue* (`/medicines/import`). Needs the *Create and edit medicines* permission.

1. Choose a CSV or Excel (.xlsx) file, or the bundled starter list. Limits: 50,000 rows, 10 MB.
2. **Preview.**
   - Columns are mapped automatically from common header names (Item Name, Salt, Company, GST %, HSN, Packing…).
     You can change any mapping and re-check.
   - Every row is validated, and shown as *new*, *update*, *duplicate (skipped)* or *error*, with the reason and the row number in your file.
3. **Import.**
   - All valid rows are written in one transaction. If anything fails, nothing is imported.
   - Rows with errors and duplicates are skipped.
   - An audit entry records the file, the mapping and the counts.

Rules:
- A catalogue entry is a **product definition only**. No batches or stock are created.
- **Duplicates.** A row is a duplicate when its normalised name matches an existing medicine, or its barcode is
  already in use. Within one file the first occurrence wins. *Skip* (the default) leaves existing medicines untouched.
  *Fill in blank details* adds a missing manufacturer, category, strength, GST rate, barcode or pack size, but never
  changes the stock unit or an existing pack size, because that would change the meaning of stock already held.
- **Missing values.** The dosage form is taken from the name when possible (Tab, Cap, Syp, Inj…). The stock unit
  follows the form (Tablet, Capsule, Bottle, Vial/Ampoule, Tube, Piece). HSN defaults to 3004. GST is left blank unless
  your file gives a rate that exists in Masters & Tax.
- **Masters.** Unknown manufacturers and categories are created by name.
- **Template:** `/api/v1/medicines/import/template`. Columns: name, generic_name, strength, dosage_form, brand_name,
  manufacturer, category, hsn_code, gst_rate, schedule_type, requires_prescription, base_unit, pack_unit, pack_size,
  barcode, reorder_level. `pack_size` accepts `15`, `10's` or `10x10`.

### Data source and licensing
- **Starter list (bundled):** `backend/data/catalogue/starter_generic_catalogue.csv`, 318 common generic formulations.
  - **Coverage:** tablets, capsules, syrups and suspensions, drops, injections and IV fluids, creams, ointments and gels, inhalers and respules, and surgical consumables.
  - **How it was made:** compiled for this project from standard generic names and commonly marketed strengths (Indian Pharmacopoeia naming; most molecules are in NLEM 2022). It contains no data copied from any proprietary or permission-restricted catalogue. It is generated by `backend/scripts/build_starter_catalogue.py`.
  - **What's left out:** brands, prices and pack sizes. GST and schedule are left for you to set. Prescription-required is set conservatively. **It is not a complete list of medicines in India.**
- **Sources investigated (26 Oct 2026):**
  - *Jan Aushadhi / PMBJP product list* (janaushadhi.gov.in, PMBI, Government of India): about 2,100 medicines and
    300 surgical items. The portal's copyright policy says material may be reproduced free of charge **after taking
    permission by email**. It was therefore **not imported**. With written permission from PMBI, export the list to
    CSV and import it here.
  - *data.gov.in* (Government Open Data License – India): only small medicine extracts from Parliament answers were
    found, not a catalogue.
  - *NLEM 2022* (MoHFW): about 384 essential medicines; no open-licence data file was found.
  - Commercial catalogues (Marg ERP and similar) are proprietary and were not used.
- **Adding a licensed catalogue:** obtain a CSV or Excel file from your distributor, from previous software you own,
  or from a licensed data vendor; preview it here; map the columns; then import. Keep the licence terms with your records.

### Purchase-order medicine search
In purchase orders, goods receipts, supplier bills and purchase returns, the medicine field is now a search box. It
searches name, brand, generic/salt, strength, dosage form, manufacturer and barcode; every word must match, so for
example "dolo 650", "amoxicillin syrup" or "azithro 500 tab" all work. Use ↑/↓ and Enter to choose. After choosing,
the unit list shows only that medicine's own units (its stock unit plus configured pack sizes), with its purchase
pack pre-selected.

## 3. Import a supplier bill
**Where:** Purchasing → *Import supplier bill* (`/purchasing/bill-import`).

| Step | What happens | Permission |
|---|---|---|
| Upload | PDF (text or scanned), JPG/JPEG, PNG or WebP, up to 10 MB and 50 pages. The type is checked from the file content; anything else is refused. The original is stored in the database (so it is included in backups) and is never modified. | Create purchases |
| Reading | Text PDFs are read from their text layer. Scanned pages and photos are read by **local OCR** (RapidOCR with ONNX models bundled in the package), **on this server; nothing is sent to any external service**. | — |
| Review (mandatory) | The original is shown beside the values read from it. Supplier and medicines are matched; uncertain values are outlined; nothing missing is invented. Edit any value; create a new supplier, medicine or pack size where needed. Totals are recalculated and compared with the printed total. A difference of more than ₹1 must be corrected, or acknowledged with an explanation. Possible duplicates (same file, same supplier + bill number) are shown; an already recorded bill blocks the import. *Save draft* at any time. | Create purchases |
| Confirm | Creates a **goods receipt** (draft) and a **supplier bill** (draft, linked to the GRN lines) using the normal purchasing services. Optionally, in the same step: **post the GRN** (adds the batches with their expiry dates, applying the pack conversion), and **finalise the bill** (creates the supplier payable and the automatic accounting posting, once accounting is set up). Everything happens in one transaction: if any step fails, nothing is saved. | Create purchases; *Post purchase invoices to stock* to post; *Finalise supplier invoices* to finalise; *Create and edit medicines* / *Create and edit suppliers* to create those |

Safeguards:
- Uploading, reading and saving a draft never change stock, payables or the books.
- An import can be confirmed only once. The supplier's bill number must be unique for that supplier in the financial year (the existing rule).
- Every upload, discard and confirmation is audited with the user and the time. The import record keeps who uploaded, reviewed and confirmed it, plus links to the GRN and the supplier bill.
- The document text is treated as untrusted input. It is only matched against number, date and code patterns, and validated (quantities, rates, GST rates, dates, batch, expiry not in the past).
- If reading fails, the import opens for manual entry; the upload is not lost.
- Phone photos must be JPEG/PNG. Set iPhones to *Most Compatible*, because HEIC is not supported.

How reliable is reading?
- Text PDFs from billing software are read accurately.
- OCR of clear scans and well-lit photos reads text accurately, but every bill layout is different. Columns are read
  using the bill's own header row and cross-checked with the arithmetic. Lines that don't add up are flagged.
- Always review before confirming.
- Brand names on bills (for example "DOLO 650") match your catalogue only if those products exist there. Otherwise
  choose an existing medicine or create one from the line.

Configuration:
- `BILL_EXTRACTOR=local` (default) or `none` (no automatic reading; manual entry only).
- No API keys are needed.
- Another engine (for example a cloud document-AI service) can be added by implementing `DocumentExtractor` in
  `backend/app/services/bill_extract.py`. Only do this deliberately: bills would then leave the server.
- Docker needs `libgl1` and `libglib2.0-0` (OpenCV, used by the OCR). They are in `backend/Dockerfile`; rebuild the backend image after updating.
